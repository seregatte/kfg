# Architecture

This document describes the internal architecture of KFG, how components relate to each other, and the design principles.

## Overview

KFG is a declarative shell compiler written in Go that transforms YAML manifests into bash functions. The architecture follows a multi-stage pipeline pattern:

```
┌─────────────┐
│   YAML      │
│  Manifests  │
└──────┬──────┘
       │
       ▼
┌─────────────────┐
│  Parser &       │
│  Validator      │
└──────┬──────────┘
       │
       ▼
┌─────────────────┐
│  Dependency     │
│  Resolver       │
└──────┬──────────┘
       │
       ▼
┌─────────────────┐
│  Kustomize      │
│  Processor      │
└──────┬──────────┘
       │
       ▼
┌─────────────────┐
│  Shell Code     │
│  Generator      │
└──────┬──────────┘
       │
       ▼
┌─────────────────┐
│  Bash Runtime   │
│  (source/exec)  │
└─────────────────┘
```

## Core Components

### 1. Parser & Validator

**Location**: `src/internal/parser/`

**Responsibilities**:
- Read YAML manifests
- Validate schema (apiVersion, kind, metadata, spec)
- Convert to internal structures

**Resource Types**:
- `Cmd`: Shell function
- `CmdWorkflow`: Cmd orchestration
- `Step`: Reusable unit of work
- `Schema`: JSON Schema Draft-07
- `Assets`: Typed data
- `Converter`: Asset transformation

**Validation example**:
```go
type Cmd struct {
    APIVersion string   `yaml:"apiVersion" validate:"required,eq=kfg.dev/v1alpha1"`
    Kind       string   `yaml:"kind" validate:"required,eq=Cmd"`
    Metadata   Metadata `yaml:"metadata" validate:"required"`
    Spec       CmdSpec  `yaml:"spec" validate:"required"`
}
```

### 2. Dependency Resolver

**Location**: `src/internal/resolver/`

**Responsibilities**:
- Build DAG (Directed Acyclic Graph) of dependencies
- Order steps by weight
- Detect cycles
- Resolve conditionals (when)

**Algorithm**:
```
1. Collect all workflow steps
2. Build dependency graph
3. Topological sort (Kahn's algorithm)
4. Apply weight ordering (stable)
5. Validate conditionals
```

**DAG example**:
```
checkout (weight: -100)
    ↓
test (weight: -90, when: checkout.STATUS == "ok")
    ↓
build (weight: -80, when: test.STATUS == "passed")
    ↓
deploy (cmd, weight: -70)
```

### 3. Kustomize Processor

**Location**: `src/internal/kustomize/`

**Responsibilities**:
- Process kustomization.yaml
- Apply overlays
- Merge resources
- Resolve references

**Flow**:
```
base/
├── kustomization.yaml
└── resources/
    ↓
overlay/
├── kustomization.yaml (references base)
└── patches/
    ↓
Merged YAML
```

**Kustomize integration**:
KFG uses the `sigs.k8s.io/kustomize/api` library to process kustomizations. This ensures full compatibility with the Kubernetes ecosystem.

### 4. Shell Code Generator

**Location**: `src/internal/shellgen/`

**Responsibilities**:
- Generate bash code from manifests
- Implement cache system
- Manage environment variables
- Generate logging functions

**Generated code structure**:
```bash
#!/usr/bin/env bash
# Generated by KFG v0.0.8
# DO NOT EDIT

# Global state
export KFG_BUILD_RESULT_FILE="/tmp/kfg-build-XXXXXX.yaml"

# Helper functions
_kfg.log.info() { ... }
_kfg.cache.store() { ... }
_kfg.cache.restore() { ... }

# Step functions
_kfg.step.checkout() {
    # Check cache
    if _kfg.cache.restore "checkout_v1"; then
        return 0
    fi
    
    # Execute
    git clone "$REPO_URL" /tmp/build
    local STATUS="checked_out"
    
    # Store in cache
    _kfg.cache.store "checkout_v1" "$STATUS"
    
    # Export output
    export KFG_STEP_checkout_STATUS="$STATUS"
}

# Cmd functions
hello() {
    _kfg.step.checkout
    echo "Hello, World!"
}
```

**Placeholders**:
```
Template: {env:VAR_NAME}
    ↓ (Go stage)
Generated: $VAR_NAME
    ↓ (Shell runtime)
Runtime: variable_value
```

### 5. Bash Runtime

**Location**: N/A (generated code)

**Responsibilities**:
- Execute generated shell functions
- Manage global state
- Implement runtime cache
- Structured logging

**Global Variables**:
```bash
KFG_BUILD_RESULT_FILE  # Build result file
KFG_STORE_DIR          # Store directory (~/.kfg/store)
KFG_VERBOSE            # Verbosity level (0-5)
KFG_STEP_<name>_<out>  # Step outputs
```

## Package-Oriented Architecture

KFG follows a package-oriented architecture:

```
packages/
├── framework/              # Shared primitives
│   ├── manifests/          # Reusable steps
│   │   ├── materialize/    # Asset materialization
│   │   ├── cleanup/        # Resource cleanup
│   │   └── detect-agent/   # AI agent detection
│   └── tests/              # Framework tests
│
└── domains/
    └── ai-agents/          # AI agents domain
        ├── manifests/      # Domain-specific resources
        │   ├── commands/   # Agent commands
        │   ├── steps/      # Agent steps
        │   └── workflows/  # Agent workflows
        ├── overlays/       # Environment overlays
        │   └── dev/        # Development overlay
        └── tests/          # Domain tests
```

**Principles**:
- **Framework**: Generic and reusable primitives
- **Domains**: Business-domain-specific packages
- **Overlays**: Base + customization composition
- **Tests**: Tests at every level (framework, domain, integration)

## Data Flow

### Application Flow

```
1. kfg apply -k overlays/dev --workflow agents
   ↓
2. Parser reads kustomization.yaml
   ↓
3. Kustomize processes overlays
   ↓
4. Resolver builds dependency DAG
   ↓
5. ShellGen generates bash code
   ↓
6. Code is sourced into current shell
   ↓
7. Functions become available
```

### Execution Flow

```
1. User runs: agents
   ↓
2. Workflow function is called
   ↓
3. Steps execute in order (weight)
   ↓
4. Cache is checked for each step
   ↓
5. Outputs are exported as variables
   ↓
6. Conditionals (when) are evaluated
   ↓
7. Cmds execute
   ↓
8. After steps execute (cleanup)
```

## Cache System

**Location**: `src/internal/cache/`

**Architecture**:
```
~/.kfg/store/cache/
├── <hash1>/
│   ├── metadata.json
│   └── data
├── <hash2>/
│   ├── metadata.json
│   └── data
└── ...
```

**Hash Calculation**:
```
hash = SHA256(step.run + step.env + step.output)
```

**Invalidation**:
- Manual: `KFG_REFRESH=1`
- Automatic: Manifest change (different hash)
- Temporal: `kfg sys cache prune` (> 30 days)

## Logging System

**Location**: `src/internal/logging/`

**Architecture**:
```
Logs → JSONL file (~/.local/state/kfg/logs/kfg.jsonl)
     ↓
     Console (based on KFG_VERBOSE)
```

**Levels**:
```
0: Quiet (no output)
1: Error + Warn + Info
2: + Detail
3: + Warn/Detail
4: + Debug
5: + Debug verbose
```

**JSONL structure**:
```json
{
  "timestamp": "2026-06-08T10:30:00Z",
  "level": "info",
  "component": "shellgen",
  "session_id": "abc123",
  "message": "Generated 5 functions"
}
```

## Extension System

**Location**: `packages/framework/manifests/extensions/`

**Architecture**:
```
base/extensions/<name>/
├── kustomization.yaml
├── assets/
│   └── mcp.yaml         # MCP configuration
└── steps/
    └── install.yaml     # Installation step
```

**Flow**:
```
1. Extension declared in kustomization
   ↓
2. Assets loaded (MCP config)
   ↓
3. Installation step executed
   ↓
4. Extension available for use
```

## Design Principles

### 1. Declarative Over Imperative

**Bad** (imperative):
```bash
#!/bin/bash
git clone repo
cd repo
make test
if [ $? -eq 0 ]; then
    make build
    if [ $? -eq 0 ]; then
        make deploy
    fi
fi
```

**Good** (declarative):
```yaml
kind: CmdWorkflow
spec:
  before:
    - step: checkout
    - step: test
      when: checkout.STATUS == "ok"
    - step: build
      when: test.STATUS == "passed"
  cmds: [deploy]
```

### 2. Composition Over Inheritance

```yaml
# base/cmd.yaml
kind: Cmd
metadata:
  name: base.cmd.deploy
spec:
  run: kubectl apply -f manifests/

---
# overlay/patch.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
patches:
  - target:
      kind: Cmd
      name: base.cmd.deploy
    patch: |
      - op: add
        path: /spec/env
        value:
          ENV: production
```

### 3. Cache by Default

Steps are automatically cached when marked as cacheable:

```yaml
kind: Step
metadata:
  annotations:
    kfg.dev/cacheable: "true"
```

### 4. Fail Fast

Validation happens at parsing time, not at runtime:

```go
// Parser validates schema
if manifest.APIVersion != "kfg.dev/v1alpha1" {
    return fmt.Errorf("unsupported apiVersion: %s", manifest.APIVersion)
}
```

## Performance Considerations

### Parsing

- **O(n)** where n = number of manifests
- Parallel: each file parsed in separate goroutine

### Dependency Resolution

- **O(V + E)** where V = steps, E = dependencies
- Kahn's algorithm for topological sort

### Shell Generation

- **O(n)** where n = number of generated functions
- Optimized template engine (text/template)

### Cache

- **O(1)** for lookup (hash-based)
- **O(n)** for prune (iterate entries)

## Security Considerations

### 1. Input Validation

All manifests are validated before processing:
- Schema validation
- Type checking
- Required fields

### 2. No Code Injection

Placeholders are resolved safely:
```go
// Bad: code injection
code := fmt.Sprintf("echo %s", userInput)

// Good: proper escaping
code := fmt.Sprintf("echo %q", userInput)
```

### 3. Sandboxing

Steps execute in isolated subshells:
```bash
_kfg.step.my_step() (
    # Subshell - variables don't leak
    local VAR="value"
    echo "$VAR"
)
```

## Testing Strategy

### Unit Tests

**Location**: `src/internal/*_test.go`

```go
func TestParser_ValidManifest(t *testing.T) {
    manifest := `
apiVersion: kfg.dev/v1alpha1
kind: Cmd
metadata:
  name: test.cmd.hello
spec:
  run: echo "hello"
`
    cmd, err := parser.ParseCmd([]byte(manifest))
    assert.NoError(t, err)
    assert.Equal(t, "test.cmd.hello", cmd.Metadata.Name)
}
```

### Integration Tests

**Location**: `tests/bats/`

```bash
@test "apply generates shell code" {
    run kfg apply -f test.yaml --workflow test
    [ "$status" -eq 0 ]
    [[ "$output" =~ "test_function()" ]]
}
```

### E2E Tests

**Location**: `packages/*/tests/`

Full tests with real manifests and complex workflows.
